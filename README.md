# Паника-режим

Веб-приложение для студента, у которого горит дедлайн, завтра экзамен или сломался код, а с чего начать, непонятно. Выбираешь, что случилось, по желанию пишешь пару слов о ситуации и получаешь план из 3–7 коротких шагов. Каждый шаг занимает 5–30 минут и начинается с глагола, так что его можно начать прямо сейчас.

Что умеет:

- шесть типов проблем: дедлайн, экзамен завтра, долг по предмету, сломался код, не понимаю тему, всё сразу;
- описание ситуации до 300 символов со счётчиком;
- чек-лист с прогрессом «3 из 5» и поздравлением в конце;
- кнопка «Разбей этот шаг ещё мельче»: подшаги появляются прямо под шагом;
- сохранение сценариев в браузере: список, открыть, удалить. Отметки переживают перезагрузку страницы;
- офлайн-план, если сервис недоступен.

Регистрации и базы данных нет, всё хранится в `localStorage`.

## Запуск локально

Нужны Node.js 20+ и аккаунт на Vercel.

```bash
cp .env.example .env
# вставь в .env свой ключ: MISTRAL_API_KEY=...
npx vercel dev
```

Приложение откроется на http://localhost:3000. `vercel dev` поднимает статику и функцию `api/plan.js` вместе и сам подхватывает `.env`. При первом запуске он попросит войти и привязать проект.

Без ключа и без Vercel тоже можно: подойдёт любой статический сервер, например `python3 -m http.server`. API тогда не ответит, и приложение покажет офлайн-планы. Так удобно проверять интерфейс.

Тесты:

```bash
npm test
```

Зависимостей нет, используется встроенный `node:test`.

## Деплой на Vercel

1. Залей репозиторий на GitHub и импортируй его на vercel.com (New Project). Фреймворк: Other, команду сборки оставь пустой.
2. В настройках проекта открой Settings → Environment Variables и добавь `MISTRAL_API_KEY` для Production (и Preview, если нужно). По желанию там же задаётся `MISTRAL_MODEL`.
3. Нажми Deploy. Если ключ добавлен после деплоя, сделай Redeploy, иначе функция его не увидит.

Можно и из терминала: `npx vercel` для превью, `npx vercel --prod` для продакшена, ключ добавляется командой `npx vercel env add MISTRAL_API_KEY`.

## Архитектура

```
index.html            разметка, карточки типов, форма, контейнеры плана и списка
css/style.css         переменные темы (светлая/тёмная), базовые стили, компоненты
js/app.js             состояние приложения и обработчики событий
js/plan.js            чистая логика: типы проблем, валидация шагов, прогресс, подшаги
js/api.js             запрос к /api/plan, таймаут, разбор ошибок
js/storage.js         localStorage с try/catch и проверкой формы данных
js/render.js          отрисовка; пользовательский текст попадает в DOM только через textContent
js/fallback.js        шаблонные планы по каждому типу проблемы
api/plan.js           serverless-функция: проверка запроса, rate limit, вызов Mistral
tests/                тесты на node:test
vercel.json           maxDuration функции 20 с, чтобы успевал отработать таймаут к Mistral
```

Как идёт запрос:

1. Браузер отправляет `POST /api/plan` с `{ type, description }`. Для разбиения шага добавляется `step`.
2. Функция проверяет метод, тип по белому списку, длину описания и лимит запросов с IP (10 в минуту).
3. Функция зовёт Mistral (по умолчанию `ministral-14b-latest`, `response_format: json_object`, temperature 0.4) с таймаутом 15 секунд.
4. Ответ модели проверяется: массив `steps`, строки разумной длины, минуты числом. Если проверка не прошла, клиент получает короткую ошибку.
5. Клиент ещё раз проверяет ответ той же функцией и рисует план. При любой ошибке сервиса показывается шаблонный план.

## Ключевые решения

**Serverless-прокси вместо запроса из браузера.** Ключ Mistral нельзя класть во фронтенд: его увидит любой, кто откроет DevTools. Поэтому ключ лежит только в переменной окружения Vercel, а браузер общается с нашей функцией. Заодно в функции удобно проверять ввод, ограничивать частоту запросов и чистить ответ модели. Ошибки наружу уходят короткие, без деталей от Mistral, а в логи пишется только HTTP-статус.

**Офлайн-план вместо экрана ошибки.** Приложением пользуются в панике. Если в этот момент показать «Ошибка 502», человеку станет только хуже. Поэтому при недоступном API, таймауте или мусорном ответе модели показывается заранее подготовленный план под выбранный тип проблемы с плашкой «Показан офлайн-план» и кнопкой повтора. Если повтор тоже не удался, текущий план с отметками остаётся на месте. Для «Разбей мельче» шаблона нет: шаг конкретный, шаблон его не разобьёт, поэтому там показывается ошибка с кнопкой «Повторить».

**Модель настраивается через `MISTRAL_MODEL`.** Изначально планировалась `mistral-small-latest`, но на бесплатном тарифе у неё лимит 0 запросов в минуту, и каждый запрос получал 429. По умолчанию стоит `ministral-14b-latest`: она доступна (30 запросов в минуту) и на тестах дала шаги точнее, чем `ministral-8b-latest`. Если тариф позволяет, модель меняется в настройках Vercel без правки кода.

**Одна валидация на сервере и клиенте.** Функция `validateSteps` лежит в `js/plan.js` и импортируется и браузером, и `api/plan.js`. Правила проверки ответа модели живут в одном месте и покрыты тестами.

## Состояния интерфейса

| Состояние | Как выглядит |
|---|---|
| loading | кнопка `disabled` со спиннером, скелетон плана; повторный клик ничего не отправляет |
| empty | пустой список сохранённых с подсказкой, что делать |
| error | сообщение рядом с действием и кнопка «Повторить» (разбиение шага, сохранение, некорректный запрос) |
| fallback | шаблонный план и плашка «Показан офлайн-план» с причиной и повтором |
| success | план с прогрессом, поздравление при выполнении всех шагов |

Статусы («План готов», «Выполнено 3 из 5», «Сценарий сохранён») озвучиваются скринридерам через `aria-live`.

## Известные ограничения

- Rate limit хранится в памяти функции. У Vercel может работать несколько экземпляров одновременно, и у каждого свой счётчик, так что лимит примерный. Для строгого лимита нужно внешнее хранилище, например Redis.
- Данные живут только в этом браузере: на другом устройстве или после очистки данных сайта сценариев не будет.
- Если открыть приложение в двух вкладках, изменения из одной могут затереть изменения из другой.
- Сохраняется до 50 сценариев.
- Офлайн-планы общие и не учитывают описание ситуации.
- Пока ждём ответ на «Разбей мельче», план можно сменить. Тогда ответ просто отбрасывается.
- Модель иногда может предложить шаг, который не совсем подходит к ситуации. Проверка гарантирует формат, а не смысл.
