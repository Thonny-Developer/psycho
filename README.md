# Паника-режим

Веб-приложение для студента, у которого навалилось всё сразу: горит дедлайн, завтра экзамен, висит долг или сломался код. Сначала оно помогает успокоиться, потом выслушивает и в конце раскладывает завал на 3–7 маленьких шагов с оценкой времени.

Приложение не заменяет психолога и честно об этом говорит. Если человеку по-настоящему плохо, кнопка «Живая помощь» в шапке ведёт к телефонам доверия.

## Как это работает

1. **Знакомство.** Три экрана: что это, как устроено, честно о границах. Показываются один раз.
2. **Главная.** Большая кнопка «Мне плохо прямо сейчас» сразу ведёт к дыханию без вопросов. Ниже шесть карточек с типами проблем и кнопка «Своя ситуация»: они сразу открывают разговор, без дыхания. Ещё ниже последние сохранённые планы.
3. **Успокоение.** Только по кнопке «Мне плохо прямо сейчас». Дыхание 4-2-6 (вдох 4 секунды, пауза 2, выдох 6), круг дышит вместе с человеком. Вторая техника: заземление 5-4-3-2-1.
4. **Разговор.** AI выясняет, что случилось, задаёт по одному вопросу за раз и помогает по делу. Есть быстрые ответы: «Не знаю, с чего начать», «Боюсь не успеть», «Просто выговориться». Когда задача понятна, AI сам собирает план через инструмент `create_plan`: в чате появляется карточка «План готов» и открывается экран плана. Собрать план можно и в любой момент кнопкой «Составить план».
5. **План.** 3–7 шагов по 5–60 минут, первый самый лёгкий. Любой шаг можно «разбить ещё мельче». Отмеченный шаг зачёркивается, прогресс растёт.
6. **Готово.** Когда отмечен последний шаг, открывается экран «Все шаги сделаны», а план сам сохраняется в «Мои сценарии».

Ещё есть настройки (тема, размер текста, меньше анимаций, удаление всех данных) и экран «Живая помощь» с номерами для Казахстана.

Регистрации и базы данных нет: всё хранится в `localStorage` этого браузера.

## Запуск локально

Нужны Node.js 20+ и аккаунт на Vercel.

```bash
cp .env.example .env
# вставь в .env свой ключ: MISTRAL_API_KEY=...
npx vercel dev
```

Приложение откроется на http://localhost:3000. `vercel dev` поднимает статику вместе с функцией `api/plan.js` и сам подхватывает `.env`. При первом запуске он попросит войти и привязать проект.

Без ключа и без Vercel тоже можно: подойдёт любой статический сервер, например `python3 -m http.server`. AI тогда не ответит. В чате появится сообщение об ошибке с кнопкой «Показать офлайн-план», а дыхание, заземление и сохранённые планы работают как обычно.

Тесты:

```bash
npm test
```

Зависимостей нет, используется встроенный `node:test`.

## Деплой на Vercel

1. Залей репозиторий на GitHub и импортируй его на vercel.com (New Project). Фреймворк: Other, команду сборки оставь пустой.
2. В Settings → Environment Variables добавь `MISTRAL_API_KEY` для Production (и Preview, если нужно).
3. Нажми Deploy. Если ключ добавлен после деплоя, сделай Redeploy, иначе функция его не увидит.

Необязательная переменная `MISTRAL_MODEL` задаёт модель. По умолчанию стоит `ministral-14b-latest`.

Из терминала: `npx vercel` для превью, `npx vercel --prod` для продакшена, `npx vercel env add MISTRAL_API_KEY` для ключа.

## Аккаунты (Supabase)

Без аккаунта всё работает как раньше: данные лежат в `localStorage`. Аккаунт нужен, чтобы планы не потерялись и были на любом устройстве. Дыхание, заземление и «Живая помощь» доступны всегда, со входом и без.

Если переменные Supabase не заданы, приложение просто не показывает вход: остаётся режим гостя.

### Настройка

1. Создай проект на [supabase.com](https://supabase.com).
2. Примени миграции из `supabase/migrations/` по порядку: в панели SQL Editor вставь и выполни каждый файл, либо через CLI `supabase link` и `supabase db push`.
3. Authentication → URL Configuration: в Site URL адрес продакшена, в Redirect URLs он же и `http://localhost:3000/` для `vercel dev`.
4. Authentication → Providers → Email: включено. Подтверждение почты можно оставить: после регистрации приложение покажет экран «Проверь почту».
5. Вход через Google: в Google Cloud Console создай OAuth Client (Web), в Authorized redirect URIs добавь `https://<project>.supabase.co/auth/v1/callback`. Client ID и Secret вставь в Supabase → Providers → Google.
6. В Vercel → Settings → Environment Variables добавь `SUPABASE_URL` и `SUPABASE_ANON_KEY` (Project Settings → API). Anon key публичный по замыслу: данные защищают политики RLS. Для удаления аккаунта нужен ещё `SUPABASE_SERVICE_ROLE_KEY`: он используется только в `api/account.js` и в браузер не попадает никогда.
7. Проверить политики: `psql "<строка подключения>" -v ON_ERROR_STOP=1 -f supabase/tests/rls_test.sql`. Скрипт работает в транзакции и всё откатывает.

Письма для подтверждения и сброса пароля шлёт встроенный почтовый сервис Supabase. У него низкий лимит, всего несколько писем в час, поэтому для настоящего запуска стоит подключить свой SMTP (Authentication → Emails → SMTP Settings).

### Данные и доступ

| Таблица | Что хранит | Кто пишет |
|---|---|---|
| `profiles` | имя, часовой пояс, дата начала, отметка о переносе гостевых данных | создаётся триггером при регистрации, дальше владелец |
| `plans` | планы аккаунта: шаги, подшаги, сохранён ли в «Мои сценарии» | владелец; `created_at`, `updated_at`, `completed_at` ставит триггер на сервере |

В `profiles` ещё хранятся аватар (один из восьми встроенных рисунков) и время ежедневного напоминания.

На всех таблицах включён Row Level Security: каждая политика проверяет `user_id = auth.uid()`, поэтому чужие строки не видны и не меняются. Время завершения плана сервер ставит сам, когда отмечены все шаги, так что подделать его с клиента нельзя.

Разговоры с AI в базу не попадают: они остаются только на устройстве.

### Как устроено в приложении

- `js/auth.js` лениво загружает `js/vendor/supabase.js` (своя копия библиотеки, без CDN) и оборачивает вход, регистрацию, Google, сброс пароля и выход.
- У гостя и у каждого аккаунта своё пространство ключей в `localStorage`. После выхода кеш аккаунта на устройстве стирается, а данные гостя возвращаются. Под другим аккаунтом чужие данные не видны.
- `js/sync.js` держит очередь изменений: интерфейс работает с локальным кешем, а правки уходят на сервер в фоне. Без сети очередь ждёт, выйти с неотправленными изменениями приложение не даст.
- При первом входе приложение один раз предлагает перенести гостевые планы. Строки вставляются с `ignoreDuplicates`, повторный перенос дублей не создаёт.
- Если сессия закончилась, данные остаются на месте, а приложение просит войти снова.
- Профиль: аватар из набора мягких рисунков (`js/avatars.js`, без загрузки фото), имя, дата начала, статистика, смена пароля, тема, размер текста, время напоминания.
- «Скачать мои данные» собирает профиль, планы и текущий разговор в JSON прямо в браузере.
- «Удалить аккаунт» требует написать слово «удалить». Сервер (`api/account.js`) проверяет токен и удаляет ровно этого пользователя через service role, а строки в таблицах уходят каскадом.
- Напоминание пока только настройка: время сохраняется, но уведомления не отправляются. Это будущая функция: для неё нужны веб-push и серверное расписание.
- `api/plan.js` проверяет токен через Supabase Auth. Лимит запросов к AI считается по аккаунту (30 в минуту), у гостя по IP (20 в минуту).

## Серия

Правило в приложении звучит одним предложением: «День засчитывается, когда все планы, с которыми ты работаешь в этот день, закрыты».

Подробнее:
- в день D активны планы, которые в этот день составлены или в которых отмечался пункт; старые нетронутые планы серию не блокируют;
- день засчитан, если все активные планы закрыты и хотя бы один закрыт именно в D;
- раз в календарную неделю (пн–вс) один пропущенный день становится днём отдыха и серию не прерывает;
- незаконченный сегодняшний день серию не обнуляет, а ставит «под угрозу»: «Осталось 2 шага, чтобы сохранить серию»;
- день считается по часовому поясу человека (у аккаунта — из профиля, он обновляется при входе), а не по UTC.

Логика лежит в чистом модуле `js/streak.js` и покрыта тестами: смена дня, часовые пояса, полночь, переход на летнее время, день отдыха, пропуски, несколько планов за день, конец месяца и года.

Защита от накрутки: у аккаунта засчитанные дни пишет только триггер в базе (`supabase/migrations/…_streak.sql`) по серверному времени. У клиента нет прав на запись в `streak_days` и `plan_activity`, поэтому ни подставить день задним числом, ни записать его напрямую нельзя. Проверка — `supabase/tests/streak_test.sql`. Приложение показывает прошлые дни с сервера, а сегодняшний считает само, чтобы отклик был сразу.

У гостя серия считается на устройстве и помечена «не сохранена в аккаунте». При переносе гостевых данных в аккаунт старая гостевая серия не переносится: на сервере засчитываются только дни, прожитые с аккаунтом.

Бейджи «3 дня подряд», «Неделя» и «Месяц» выдаются по лучшей серии.

## Библиотека

Раздел «Библиотека» (во вкладке «Книги»): 12 известных книг о тревоге, прокрастинации, учёбе, самооценке и работе без выгорания. Поиск, фильтр по темам, карточка книги с 3–5 главными идеями и блоком «Попробуй сегодня», отметки «Хочу прочитать / Читаю / Прочитано». Блок «Подобрано под твою ситуацию» выбирает книги по типу проблемы недавнего плана.

Данные лежат в `data/books.json`, а не в базе: это справочник, одинаковый для всех, его удобно проверять и править в репозитории. В базе (`book_status`, под RLS) хранятся только отметки человека; у гостя они в `localStorage`.

Поля книги: `id`, `title`, `author`, `topics[]` (`stress`, `procrastination`, `study`, `self`, `energy`), `pitch` (2–3 строки: о чём и кому поможет), `key_ideas[]` (3–5), `try_today` (одно маленькое действие), `reading_time` (примерная оценка в минутах), `source_url`, `needs_review`.

Как добавить книгу:
1. Допиши объект в `data/books.json`. Описание и идеи — своими словами, без цитат и пересказа больших кусков.
2. Если не уверен в названии издания, авторе или деталях — `needs_review: true`. Ссылку не выдумывай: если сомневаешься, `source_url: null`.
3. Запусти `npm test`: тест проверит формат и что ни одна ссылка не появилась без проверки.

Сейчас `needs_review: true` у пяти книг: у них русские названия разных изданий отличаются (например, «Съешьте лягушку!» выходила под названием «Оставьте брезгливость, съешьте лягушку!»). Перед защитой стоит сверить. Текстов и файлов книг в репозитории нет.

## Архитектура

```
index.html               оболочка: шапка, плашка «Нет сети», сцена для экранов, слой диалогов
css/style.css            токены светлой и тёмной темы, масштаб текста, стили экранов
fonts/                   Literata и Onest (кириллица и латиница), лицензия OFL
js/app.js                состояние, сохранение, навигация, действия, отрисовка
js/screens/*.js          экраны: onboarding, home, calm, chat-screen, plan-screen, done, saved, settings, overlays
js/plan.js               чистая логика плана: типы, проверка ответа модели, прогресс, подшаги, перенос старых данных
js/chat.js               кризисные фразы, история для API, проверка реплики модели
js/breath.js             фазы дыхания и анимация круга
js/storage.js            localStorage с try/catch, проверкой формы данных и переносом из первой версии
js/api.js                запросы к /api/plan, таймаут, разбор ошибок
js/fallback.js           шаблонные планы по каждому типу проблемы
js/content.js            тексты, приветствия, шаги заземления, номера помощи
js/ui.js, js/icons.js    создание DOM-элементов, иконки
api/plan.js              serverless-функция: проверка запроса, rate limit, вызов Mistral
tests/                   тесты на node:test
```

Каждый экран — функция, которая один раз строит DOM и дальше обновляет только меняющиеся части. Так поле ввода в чате не теряет курсор, круг дыхания двигается без перерисовки экрана, а фокус после действий остаётся на месте.

### API: `POST /api/plan`

Одна функция, действие выбирается полем `action`:

| action | что отправляет клиент | что возвращает |
|---|---|---|
| `chat` | `type`, `messages` (последние 20 реплик) | `{ reply }`: 1–3 предложения, не больше одного вопроса; или `{ plan }` / `{ reply, plan }`, если модель вызвала `create_plan` |
| `plan` | `type`, `messages` | `{ title, steps: [{ title, minutes }] }`, 3–7 шагов; вызов `create_plan` обязателен |
| `split` | `type`, `planTitle`, `step`, `stepMinutes` | `{ steps }`, 2–4 подшага |

`type` — одна из тем меню, `other` для своей ситуации или `null` для «Мне плохо прямо сейчас».

Функция проверяет метод, действие, тип по белому списку, роли и длину реплик (до 500 символов каждая, до 8000 всего) и лимит запросов (20 в минуту с одного IP). Для чата и плана Mistral получает инструмент `create_plan` (в чате `tool_choice: auto`, по кнопке `any`), для разбиения шага — `response_format: json_object`. Таймаут 15 секунд. Ответ модели проверяется теми же функциями, что и на клиенте, а наружу уходят только короткие сообщения об ошибках, без деталей от Mistral.

## Безопасность

- Ключи Mistral и Supabase service role живут только в переменных окружения Vercel.
- Строгая Content Security Policy в `vercel.json`: скрипты, стили и шрифты только со своего домена, сетевые запросы только к своему API и Supabase, встраивание в чужие сайты запрещено.
- Пользовательский текст попадает в DOM только через `textContent`, `innerHTML` в проекте не используется.
- Все пользовательские таблицы под RLS, проверки длины и формата и на клиенте, и в базе.

## Ключевые решения

**Serverless-прокси вместо запроса из браузера.** Ключ Mistral нельзя класть во фронтенд: его увидит любой, кто откроет DevTools. Поэтому ключ лежит только в переменной окружения Vercel, а браузер общается с нашей функцией. В логи пишется только HTTP-статус от Mistral.

**Офлайн-план вместо экрана ошибки.** Приложением пользуются в панике, и «Ошибка 502» в этот момент только добавит тревоги. Если AI недоступен, план собирается из готового шаблона под выбранный тип проблемы. Сверху плашка «Показан офлайн-план» с причиной и кнопкой «Повторить». Если повтор не удался, план с отметками остаётся на месте. Для «Разбей ещё мельче» шаблона нет: общий шаблон не может разбить конкретный шаг, поэтому там показывается ошибка с повтором.

**Кризисные фразы проверяются на устройстве.** Сообщение вроде «выхода нет» не отправляется в AI. Приложение сразу показывает спокойный ответ, карточку «С живым человеком бывает легче» и открывает «Живую помощь». Эти реплики помечаются как личные и не попадают в историю для AI. Дополнительно в системном промте модели сказано мягко направлять к живой помощи.

**План собирается инструментом.** У модели есть функция `create_plan` со схемой шагов. В чате модель сама решает, хватает ли информации: если да, вызывает инструмент, если нет, задаёт один вопрос обычным текстом. В промте прямо сказано, что тема из меню только подсказка, а главное — что написал человек. Поэтому план по разговору «да не экзамен, поругалась с соседкой и не могу сделать лабу» получается про соседку и лабу, а не про экзамен. Аргументы инструмента проверяются той же `validatePlan`, что и всё остальное. Если модель всё же заворачивает реплику в JSON вида `{"reply": "..."}`, обёртка снимается и в чате остаётся только текст.

**Одна проверка на сервере и клиенте.** `validateSteps`, `validatePlan`, `validateReply` и `validateMessages` лежат в `js/` и импортируются и браузером, и функцией. Правила живут в одном месте и покрыты тестами.

**Шрифты лежат в проекте.** Literata и Onest не грузятся с Google Fonts, поэтому приложение выглядит так же без сети и не отправляет запросы третьей стороне.

**Модель настраивается.** `mistral-small-latest` на бесплатном тарифе отдаёт лимит 0 запросов в минуту. `ministral-14b-latest` доступна и на тестах дала шаги точнее, чем `ministral-8b-latest`.

## Состояния интерфейса

| Состояние | Где видно |
|---|---|
| loading | «печатает…» в чате, скелетон плана «Думаю, как разложить по шагам…», скелетон подшагов; кнопки на время запроса неактивны |
| empty | «Пока пусто» в «Моих сценариях» и на главной |
| error | карточка в чате с «Повторить» и «Показать офлайн-план», ошибка под шагом при разбиении |
| fallback | офлайн-план с плашкой и причиной |
| offline | плашка «Нет сети» под шапкой |
| success | план, прогресс, тост «Сохранено», экран «Все шаги сделаны» |

Статусы озвучиваются скринридерам через `aria-live`. Всё управляется с клавиатуры. Пока открыт диалог, остальная страница недоступна для фокуса, Escape его закрывает. Контраст текста по WCAG AA проверен для обеих тем.

## Известные ограничения

- Rate limit хранится в памяти функции. У Vercel может работать несколько экземпляров одновременно, и у каждого свой счётчик, так что лимит примерный.
- Список кризисных фраз — эвристика: он ловит частые формулировки, но не все. Поэтому кнопка «Живая помощь» есть на каждом экране.
- Модель иногда пишет слова с родом («уверен», «написал»), хотя в промте просили так не делать. Формат ответа проверяется, смысл нет.
- Данные живут только в этом браузере. На другом устройстве или после очистки данных сайта их не будет. Если открыть приложение в двух вкладках, изменения из одной могут затереть изменения из другой.
- Сохраняется до 50 сценариев.
- Офлайн-планы общие и не учитывают разговор.
- Номера помощи только для Казахстана.
- Лимит запросов к AI хранится в памяти функции (см. выше), проверка токена кешируется на минуту: если отозвать сессию, лимит по ней ещё минуту считается по аккаунту.
- Встроенная почта Supabase отправляет мало писем в час; для настоящего запуска нужен свой SMTP.
